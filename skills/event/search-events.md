# search-events — 搜索活动

`GET /open/events/search` · 鉴权：Bearer apiKey

按关键词模糊搜索当前用户可见的正常活动，匹配标题和内容，不区分大小写。只返回已发布、报名中、报名截止、进行中或已结束的活动。
`keyword` 不传、传空字符串或纯空格时表示不按关键词过滤，返回全部可见活动。

## 请求

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `keyword` | string | 否 | 搜索关键词，去除首尾空格后最长 32 字；不传或为空表示不按关键词过滤 |
| `count` | number | 是 | 分页大小，1-100 |
| `next` | string | 是 | 第一页传空字符串 |

## 响应

| 字段 | 描述 |
|------|------|
| `data.page` | 分页信息，`data.page.next` 为空字符串表示没有下一页 |
| `data.total` | 当前条件下的可见活动总数，仅第一页返回 |
| `data.list` | 活动列表；无匹配时为 `[]` |

`data.list[]` 的完整字段、状态枚举与活动关系结构见 `query-result.md`，调用本接口时一并读取。

## 注意

- **`keyword` 可不传**：用户说「最近有什么活动」这类没有关键词的诉求时，可以直接不传 `keyword` 查询，返回全部可见活动，不必先追问方向。
- 不传关键词时按「距首次请求时间越近越靠前」排序，同距离时未来活动优先，已结束的活动也在结果中。用户明确要「还没开始的活动」时，先从结果里筛 `startTime` 晚于当前时间的项再展示，不要承诺列表都是即将开始的活动。
- `buttonStatus` 是当前用户可执行动作的权威判断：`13` 可报名、`11` 可候补、`8` 已报名、`5` 审核中、`12` 报名截止。
- 列表用编号展示标题、时间、地点、状态；活动状态与按钮状态都转成中文，不要直接展示数字；`venueText` 已是可展示的地点文案。
- `venue` 只在公开或已报名 / 主理人时返回完整内容；返回 `{}` 时说明当前不可见，不要向用户透露地点细节。
- 用户选中活动后按 `signup-event.md` 报名。
- 没有搜索结果时回复「没有找到相关活动，换个关键词试试？」。

## 示例

```bash
curl "${FARBAY_OPEN_HOST}/open/events/search?keyword=%E6%8A%80%E6%9C%AF&count=10&next=" \
  -H "Authorization: Bearer ${FARBAY_OPEN_API_KEY}"
```
